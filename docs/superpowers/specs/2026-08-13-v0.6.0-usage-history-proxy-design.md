# Codex SwitchBridge 0.6.0 Usage History and Quota Reliability Design

Status: Approved by the user's standing instruction to use the recommended design without further confirmation

Date: 2026-08-13

## Goal

Make ChatGPT account quota and reset data reliably visible inside the VS Code extension host, then add a truthful, interactive local-token history view with daily, weekly, and monthly grouping. Preserve account/API-provider switching, shared conversation history, bilingual UI, exact reset clocks, and secret boundaries.

## Confirmed Runtime Failure

The 0.5.1 package is installed and activated locally. A quota query with `HTTPS_PROXY=http://127.0.0.1:3128` returns the account's seven-day window; the same query from the running VS Code extension host returns `request_failed`. The host was launched with `--useHostProxy=false` and has no proxy variables, so later shell exports cannot reach it.

The production quota cache also contains thousands of pre-0.5.1 test entries. Version 0.5.1 isolates new tests, but only normalizes old entries after a successful write. Network failure prevents that write. On b200, the installed 0.5.1 package has not been loaded because the extension host predates installation, and a conflicting account-switch extension is active.

## Quota Reliability

Core quota requests accept an explicit proxy option. Resolution order is:

1. `codex-switchbridge.proxy`;
2. VS Code's `http.proxy`;
3. extension-host `HTTPS_PROXY`, `HTTP_PROXY`, or `ALL_PROXY`.

An empty extension setting means automatic resolution. Only `http:` and `https:` proxy URLs are accepted. Logs record the selected source and whether a proxy exists, never its URL or credentials. The resolved option flows through saved-account query contexts so local accounts, cloud accounts, status bar, dashboard, manual refresh, and automatic refresh share the same behavior.

Quota result logs include only sanitized business diagnostics: result kind, unavailable-reason code, status code, and number of windows. Provider mode explicitly says an API provider has no ChatGPT quota; saved ChatGPT account cards continue to show their own quota.

At activation, the legacy production cache is normalized once even when no network result can be written. The migration remains atomic and retains only valid, recent, newest-per-account entries. Test cache isolation remains unchanged.

## Local Usage History

The existing device-local v2 token index already stores timestamped token increments and account/provider selection intervals. `UsageSnapshot` gains derived UTC daily buckets without changing the persisted schema. Each bucket contains total, unattributed, estimated, and per-subject token totals. Derived history is never persisted.

Timestamped increments are assigned to their UTC calendar day and to the subject active at that time. Pre-index historical totals and undated remainders cannot be split accurately; they are assigned to the record's last observed UTC day and marked estimated. Values with no usable date go into an undated total. Totals must be conserved exactly across history buckets plus undated usage.

This avoids a mandatory full scan of roughly 1.18 GiB of existing rollout files. The UI says that older usage can be estimated and that day boundaries are UTC.

## Dashboard Interaction

The usage section follows the supplied official visual language without copying its percentage semantics:

- orange vertical bars on a quiet axis;
- segmented `Day / Week / Month` grouping;
- `All / account / API provider` subject filter;
- date range for day/week and month range for month;
- keyboard-focusable bars with localized tooltips;
- selected-range total, average, peak, and estimated amount;
- an accessible empty state and responsive horizontal chart scrolling.

The y-axis is actual locally recorded tokens, not an official quota percentage. Daily defaults to the latest 30 UTC days, weekly to 12 ISO-style Monday weeks, and monthly to 12 UTC months. Filters persist in `webview.setState()` and never cross the host protocol. English and Simplified Chinese catalogs cover every new control, tooltip, note, and empty/error state.

The page remains an operational editor dashboard. Quota and reset status stay prominent; account comparison remains separate; cards are not nested; narrow split editors stack controls without overlap. High contrast, reduced motion, long names, and keyboard navigation remain supported.

## Security and Compatibility

- No token, cookie, account ID, proxy URL, proxy credentials, raw auth, or provider secret enters the dashboard model or logs.
- No remote Webview requests or command URIs are introduced.
- Existing local token cache version stays at v2.
- Existing quota-cache format stays readable.
- API-provider mode does not claim remote ChatGPT quota or API billing data.
- Local token history is observational and device-local, not OpenAI billing or authoritative server usage.

## Verification and Release

Tests cover explicit proxy precedence and redaction, context propagation, cache activation cleanup, sanitized quota diagnostics, daily attribution/conservation/estimated history, dashboard projection, bilingual catalog parity, aggregation/filter persistence, keyboard access, themes, wide/narrow layouts, and overflow. A real quota smoke test must return a window inside the installed extension environment. The verified 0.6.0 VSIX is installed locally and on b200; b200 is reloaded and the conflicting switch extension is disabled or removed. GitHub receives a PR, merged tag, release notes, and VSIX asset. Marketplace publication is attempted with available publisher credentials; if none exist, the same VSIX is handed off for the already authenticated browser upload and the public version is verified afterward.
